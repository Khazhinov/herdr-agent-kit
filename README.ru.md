# herdr-tool-agents

[English](README.md) | Русский

Реестр папок машины, в которых настроены MCP-серверы, и небольшой CLI. Через него любой агент в любом
проекте пользуется этими серверами при помощи дешёвого агента-исполнителя в терминале
[herdr-core](https://github.com/herdrdev/herdr-core). Работает вместе с
[herdr-gsd-template](https://github.com/Khazhinov/herdr-gsd-template), но от него не зависит.

## Назначение

Агент проекта с десятью MCP-серверами загружает сотни схем инструментов в каждый запрос, а каждому
проекту нужна своя копия токенов. Здесь проект знает только короткий каталог: имя модуля, область,
имена возможностей. Запрос уходит постоянному исполнителю (по умолчанию Claude Haiku), запущенному в
папке, где лежат MCP-серверы и их секреты. Агент проекта читает короткий файл ответа.

| Свойство | Как обеспечено |
|---|---|
| Контекст проекта не растёт | проект видит несколько строк каталога (`snippet`), схем MCP не видит |
| Дешёвая модель для вызовов инструментов | `command` модуля, по умолчанию `claude --model haiku` |
| Одна настройка для всех проектов | терминал `tool-<module>` живёт в herdr-core вне проектов (`--no-parent`) |
| Секреты в одной папке | `.mcp.json` только в папке модуля; проект получает возможность, а не токен |
| Запись только с согласия человека | `--write` работает при `allow_write = true` в реестре; запрос помечается `WRITE ALLOWED BY USER` |
| Аудит | `~/.cache/herdr-tool-agents/audit.jsonl`: запрос, режим, результат, длительность |

## Состав

| Путь | В git | Назначение |
|---|---|---|
| `tool_ask.py` | да | CLI |
| `registry.example.toml` | да | пример записи реестра с пояснениями |
| `examples/<module>/` | да | образец `.mcp.example.json` для папки модуля |
| `AGENTS.md` | да | порядок работы агента, который ведёт реестр на машине |
| `local/registry.toml` | нет | модули этой машины: папки, возможности, разрешение записи |
| `local/modules/<module>.md` | нет | дополнительные правила исполнителя модуля |

## Использование

```bash
cp registry.example.toml local/registry.toml   # затем зарегистрировать реальные папки, см. AGENTS.md
./tool_ask.py list                             # каталог
./tool_ask.py snippet github                   # блок для AGENTS.md проекта
./tool_ask.py ask github "Состояние последнего запуска Actions в main репозитория X"
# -> путь к файлу ответа; последняя строка DONE
./tool_ask.py status github
./tool_ask.py stop github
```

Вывод `snippet` содержит абсолютный путь к `tool_ask.py` на этой машине. В публичном проекте его
размещают в неотслеживаемом файле (`CLAUDE.local.md`, `AGENTS.local.md` или подключаемый файл из
`.gitignore`), а не в `AGENTS.md` под git.

Из проекта на herdr-gsd-template: `python3 scripts/orch.py tools` и
`python3 scripts/orch.py tool-ask <module> "<запрос>"` (путь к реестру: `HERDR_TOOL_AGENTS` или
`[tools] hub` в `.orchestration/routing.local.toml`).

Коды выхода: 0 ответ готов, 1 ошибка или таймаут, 2 конфигурация, 3 модуль занят, 4 нужен человек
(диалог доверия, вход, запрос разрешения), 5 запись запрещена.

## Протокол запроса

1. Терминал исполнителя запускается при первом запросе и продолжает работать.
2. Перед запросом исполнитель получает `reset` (`/clear`): один запрос - один разговор.
3. Запрос содержит путь к файлу ответа и режим: только чтение или `WRITE ALLOWED BY USER`.
4. Завершение определяется по последней строке файла (`DONE` или `FAILED: ...`) и событиям herdr-core.
5. Исполнитель Claude получает правила через `--append-system-prompt`; собственные `CLAUDE.md` и
   `.mcp.json` папки модуля загружаются обычным образом.
