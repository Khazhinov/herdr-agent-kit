# Служебные репозитории

[English](service-repos.md) | Русский

## Задача

Часть репозиториев - рабочие места со своими процедурами: репозиторий документов с экспортом по
ГОСТ, репозиторий отчётов, среда проверки. Другим проектам нужны их результаты, но не копии их
правил, навыков и токенов, а каждому виду работы нужны своя среда, модель и усилие.

## Решение

Репозиторий объявляет, что он предоставляет, в манифесте `agent-service.toml` в корне. Реестр
указывает на папку (модуль вида `service`). Проект вызывает функцию по имени с типизированными
аргументами; агент-исполнитель, запущенный в этом репозитории, выполняет её по собственным
инструкциям репозитория. Манифест ведёт владелец репозитория; машина может переопределить профили.

## Манифест

```toml
[service]
description = "Documents: requirements, design notes, docx export"
profile = "writer"                 # профиль функций, которые не называют свой

[profiles.writer]                  # один способ запуска исполнителя
runtime = "claude"
model = "sonnet"
effort = "high"

[profiles.reviewer]
runtime = "codex"
effort = "medium"                  # без модели: модель среды по умолчанию

[functions.draft]
description = "Draft a document section from a source file"
run = "Follow the task life cycle of this repository's agent instructions."
params = [
  {name = "task", type = "string", required = true, description = "task folder name"},
  {name = "source", type = "path", required = true, description = "input file of the calling project"},
]
returns = "path of the new document version and a list of open questions"
writes = ["*/drafts/**"]           # пути репозитория, которые функция меняет без --write
profiles = ["writer", "reviewer"]  # порядок профилей; далее профиль [service] и `default`
timeout = 3600
# external = true                  # меняет внешнюю систему: нужны --write и allow_write
```

Образец с тремя функциями: `examples/service-docs/agent-service.toml`.

| Ключ | Значение |
|---|---|
| `params[].type` | `string`, `path`, `number`, `bool`. Путь (`path`) приводится к абсолютному в папке вызывающего: исполнитель работает в другой папке |
| `writes` | единственные пути репозитория, которые меняет функция; нет поля - файлы не меняются |
| `external` | функция меняет что-то вне репозитория; вызывающему нужен `--write` после согласия человека, модулю - `allow_write = true` |
| `profiles` | порядок профилей, который видит вызывающий; затем `[service] profile`, затем встроенный `default` |

## Профили

Профиль - среда, модель и усилие; все ключи необязательны.

| Среда | Модель | Усилие | Примечание |
|---|---|---|---|
| claude | `--model` | `--effort low..max` | следующие профили claude из цепочки передаются как `--fallback-model`: Claude Code сам переключается, если модель недоступна |
| codex | `-m` | `-c model_reasoning_effort="<level>"` | |
| opencode | `-m provider/model` | в интерактивном режиме нет | `effort` отклоняется; вариант задаётся в агенте `opencode.json` |
| другая | `command` (полный argv), `reset` | в `command` | |

Встроенный профиль `default` - среда профиля службы без модели и усилия, то есть настройки среды по
умолчанию; он работает и после переименования или снятия модели. Модели меняются; машина
переопределяет профиль в своём реестре, не трогая репозиторий:

```toml
[modules.docs.profiles.reviewer]
model = "<new model id>"
```

Автоматического повтора на другом профиле нет. Если исполнитель не запустился или закончил ход без
ответа, вызов завершается с кодом 6 и перечисляет остальные профили; вызывающий агент спрашивает
человека и повторяет вызов с `--profile <name>`.

## Вызовы

```bash
tool_ask.py call docs draft --arg task=20261104_spec --arg source=notes/meeting.md
tool_ask.py call docs draft --arg task=... --arg source=... --async     # выводит идентификатор задачи
tool_ask.py wait docs <task>                                             # или: result docs <task>
```

Исполнитель получает функцию, её инструкцию `run`, аргументы, разрешённые `writes`, каталог для
файлов вызывающему и файл ответа. Он не ждёт человека: недостающие данные или нужное решение
оформляются как `FAILED: needs: <вопрос>`. Завершение и коды выхода: [herdr-calls.ru.md](herdr-calls.ru.md).

## Изменения доходят до подключённых проектов

Манифест читается без запуска чего-либо, поэтому карточка пересобирается автоматически, если файл
новее карточки: при `call`, `card`, `link` и `sync`. Добавленные, удалённые и изменённые функции
записываются в журнал с датой и попадают в файлы каждого подключённого проекта
([linked-projects.ru.md](linked-projects.ru.md)); `call`, обнаруживший изменённый манифест, сообщает
об этом в stderr.

## Применение без этого кода

Положить в репозиторий манифест с функциями, типизированными параметрами, границами записи и
профилями; запускать агента в репозитории с флагами профиля; отправлять ему функцию, аргументы и
путь к файлу ответа; читать ответ по последней строке.
