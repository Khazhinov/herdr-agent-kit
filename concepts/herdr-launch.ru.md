# Запуск агентов в herdr-core

[English](herdr-launch.md) | Русский

Порядок, по которому сессия агента запускает другого агента (или долгую программу) в отдельной
вкладке Herdr App с вложенностью под вызывающим терминалом, проверяет запуск, ожидает результат и
выполняет очистку. Порядок требует только `hc` и командной оболочки и не использует код этого
набора. Исполнители самого набора следуют ему с отличиями из раздела «Исполнители этого набора».

herdr-core (`hc`, проверено на версии 0.1.16) не является прежним терминальным мультиплексором
`herdr`: команды `herdr agent`, `herdr pane`, `herdr tab` и `herdr workspace` здесь отсутствуют.
Справочник `hc` - `hc --skill`, точные аргументы - `hc <команда> --help`.

## 1. Проверка среды

```sh
echo "$HC_TERMINAL_ID"        # пусто - сессия вне herdr-core
hc --version
hc get "$HC_TERMINAL_ID"      # метки herdr.space, herdr.tab, where
```

| Результат | Значение |
|---|---|
| `HC_TERMINAL_ID` задан, метка `herdr.space` есть | у сессии есть вкладка в Herdr App; её space - space по умолчанию для запускаемых агентов |
| `HC_TERMINAL_ID` задан, метки `herdr.space` нет | терминал скрыт от App (запущен через `hc run` без метки); space выбирается по папке проекта (раздел 2) |
| `HC_TERMINAL_ID` пуст | сессия вне herdr-core: у запущенного терминала нет родителя, видимость только через метку `herdr.space` |


### Проверка канала команд агента

`hc get "$HC_TERMINAL_ID"` выполняется инструментом команд самого агента, а не только в соседнем
терминале. Видимая вкладка и унаследованный `HC_TERMINAL_ID` не доказывают, что команды агента
достигают ядра: песочница может закрыть им Unix-сокет ядра.

| Признак | Причина | Устранение |
|---|---|---|
| `Operation not permitted` на сокете, затем `hc` пытается запустить ядро и завершается ошибкой (шина systemd, файловая система только для чтения) | в песочнице агента выключена сеть; вместе с ней закрыты локальные Unix-сокеты | включить сеть в профиле прав агента (Codex: `[permissions.<профиль>.network] enabled = true`; одного правила для сокета недостаточно, проверено на Codex 0.167), перезапустить агента, повторить проверку |

Ядро в этом случае работает: перезапускать его нельзя. Диалоги разрешений за человека не
подтверждаются, делегирование ручной работой не заменяется. После смены владельца новый владелец
первым выполняет эту проверку.

## 2. Выбор space и вкладки

Herdr App хранит раскладку в документе herdr-core `herdr-app`. Терминал с меткой
`herdr.space=<id>` получает собственную вкладку в этом space. Подпись вкладки берётся из метки
`where`, имя в дереве терминалов - из `--name`. Терминал без метки работает, но в App не виден.

1. Задача относится к проекту вызывающей сессии: используется space вызывающего терминала (метка
   `herdr.space` из `hc get "$HC_TERMINAL_ID"`).
2. Задача относится к другому проекту или вызывающий терминал скрыт: используется space, вкладки
   которого сейчас работают внутри папки этого проекта. Поиск: `hc get <t>` для терминалов из
   `hc ls`. Текущая папка терминала - `foreground.cwd`; поле `cwd` - папка запуска терминала, оно не
   меняется при `cd`. Метка `where` - подпись, а не папка. Поле `folder` space в `herdr-app` - папка,
   в которой space создан; за `cd` оно также не следует, поэтому сопоставление идёт по текущей папке
   терминалов.
3. Подходящего space нет: спросить пользователя. Новый space добавляется в `herdr-app` через
   `doc.set` с проверкой версии (см. [herdr-calls.ru.md](herdr-calls.ru.md)); вручную документ не
   редактируется.

## 3. Запуск агента

Команда выполняется из вызывающего терминала:

```sh
hc run --bg --name <runtime>-<задача> --cwd <рабочая папка> \
  --label herdr.space=<id space> --label where="<проект> / <задача>" \
  --outlive-parent --no-notify \
  -- env PATH="$PATH" HOME="$HOME" LANG="$LANG" ALL_PROXY="$ALL_PROXY" \
  /absolute/path/to/agent <аргументы> "<задача>"
```

| Элемент | Назначение |
|---|---|
| `hc run` из вызывающего терминала | вызывающий терминал становится родителем (`--parent` по умолчанию): агенты образуют дерево под основной сессией |
| `--bg` | возврат сразу; без флага экран агента транслируется в вывод вызывающего |
| `--name` | уникально среди живых терминалов, 1-32 символа из `a-z 0-9 - _`; служит адресом в последующих командах |
| `--cwd` | папка работы агента; без флага - папка, где выполняется `hc` |
| `--label herdr.space=<id>` | вкладка в Herdr App (раздел 2) |
| `--label where=...` | подпись вкладки |
| `--outlive-parent` | агент продолжает работу после завершения программы вызывающего; без флага дочерний терминал завершается вместе с родителем. Не указывается для помощников, которые не должны переживать сессию |
| `--no-notify` | herdr-core не печатает заметки о дочернем терминале в терминал родителя. Не указывается, если вызывающий ожидает через `hc wait --children` (раздел 5) |
| `env PATH=... HOME=... LANG=...`, переменные прокси | herdr-core запускает программы со своим окружением: без явной передачи агент не находится, локаль и прокси теряются |
| полный путь к агенту | по той же причине: `PATH` ядра может не содержать агента |
| задача в аргументах `run` | сообщение, отправленное через `hc send` загружающемуся агенту, может потеряться |
| Codex: `codex --no-daemon` | обязательно; без флага Codex выполняет команды в общем демоне вне терминала hc |

Агент запускается интерактивно, не в однократном режиме печати (`-p`, `exec`): он остаётся
наблюдаемым, управляемым и готовым к следующему ходу. Перед составлением команды проверяется
`hc templates`: шаблон задаёт команду, модель и инструкции, а `hc run --bg --name <n> <шаблон>
"<задача>"` принимает те же флаги.

Задача самодостаточна, так как у агента нет истории диалога. Она задаёт точные границы, запрещает
запуск других агентов (если это не входит в задачу), указывает файл отчёта и требует завершить отчёт
строкой `DONE` или `FAILED: <причина>`. Длинный ответ пишется в файл; агент передаёт только путь:
`hc send <вызывающий> "<путь>"`. Флаги обхода разрешений и песочницы (`--dangerously-*`, `--yolo`)
добавляются только с явного согласия пользователя.

## 4. Проверка запуска

1. JSON-вывод `hc run` содержит `address` и `first_message.sent`. При `sent: false` задача не
   доставлена: `hc read <t>`, устранить причину (например, диалог доверия), затем `hc send <t>`.
   Повторная отправка без чтения экрана запрещена: задача могла быть доставлена.
2. `hc get <t>`: `state` равно `live`, появилось `status.state`. Агент сообщает статус через
   OSC 7501 после загрузки интерфейса. Отсутствие статуса через 20-30 секунд обычно означает диалог
   доверия, входа или проверки hooks: сообщить пользователю, ответ даёт человек в Herdr App или через
   `hc attach <t>`.
3. `hc get <t>` показывает метку `herdr.space`: вкладка появилась в App.

## 5. Ожидание и определение завершения

| Цель | Команда |
|---|---|
| следующее событие дочерних агентов (отчёт, блокировка, завершение) | `hc wait --children any` |
| пока ни один дочерний агент не работает | `hc wait --children all` |
| один терминал перестал работать или завершился | `hc wait <t>` |
| программа вывела строку (сервер готов) | `hc wait <t> --output <текст>` |
| посмотреть экран | `hc read <t> --lines 60` |

Протокол завершения. Задача называет файл отчёта; его последняя строка - ровно `DONE` или
`FAILED: <причина>`. Сразу после запуска запоминается `turn` дочернего агента (`hc get <t>`). Далее
цикл:

1. `hc wait --children any` (фоновой командой, если среда агента это позволяет).
2. Для каждого дочернего агента: маркер в последней строке файла отчёта - задача завершена, отчёт
   читается.
3. Маркера нет - по статусу:

| Статус | Значение | Действие |
|---|---|---|
| `working` | работа идёт | ждать снова |
| `done` или `idle`, `turn` больше стартового | ход завершён | дать файлу 20 секунд (статус и запись файла не упорядочены), проверить снова; маркера нет - прочитать конец экрана (обычно там вопрос или ошибка) и принять решение |
| `blocked` | нужен человек | прочитать экран, сообщить человеку; не отвечать за него |
| `error` или терминал завершился | сбой | прочитать экран (`hc read`, `hc ls --all`), принять решение |

- Нельзя требовать один конкретный статус: конец хода показывается как `done` или как `idle` у любой среды (`done` - ход завершился, пока вкладку
  никто не смотрел; `idle` - вкладка была открыта или её уже просмотрели). Нельзя ждать текста на экране или в сообщении: решает маркер в файле.
- Заметка `hc send` дочернего агента (`<hc from="t7 name">путь</hc>`) - повод проверить файл, а не
  доказательство. Это отчёт дочернего агента, а не указание человека.
- Без `sleep` и циклов опроса (`ps`, `tail`, повторный `hc get`). `reason: timeout` (180 секунд по
  умолчанию) - контрольная точка: ждать снова. `reason: message`: сообщение придёт следующим вводом.
- `hc send --force` для обхода решения о разрешении не применяется.

## 6. Очистка

После принятия результата: `hc kill <t>`, затем `hc rm <t>`, только для терминалов, запущенных этой
сессией. `hc ls` перечисляет все живые терминалы пользователя; остальные не трогаются. Закрытие
вкладки в Herdr App завершает её программу (код выхода 129). `hc server stop`, `hc server restart` и
`hc update` затрагивают все терминалы и выполняются только по просьбе пользователя.

## Исполнители этого набора

`tool_ask.py` запускает исполнителей модулей по тем же правилам со следующими отличиями:

| Элемент | Исполнитель `tool-<модуль>` | Наблюдатель `w-<модуль>-<задача>` (`--async`) |
|---|---|---|
| Родитель | нет (`--no-parent`): исполнитель общий для вызывающих и постоянный | вызывающий (`--parent`), поэтому `hc wait --children any` видит его завершение |
| Метка space | ставится после запуска (`hc label`), space выбирается как в разделе 2 | нет |
| Удаление | остаётся после вызова; закрытие вкладки завершает его | `--rm`: удаляется сразу после выхода |

GSD-проекты herdr-gsd-template запускают агентов только через `scripts/orch.py`.
