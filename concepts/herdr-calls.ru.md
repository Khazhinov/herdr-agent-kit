# Вызовы через herdr

[English](herdr-calls.md) | Русский

Один протокол обслуживает всех исполнителей, в какой бы среде ни работали вызывающий и исполнитель.
Вызывающему нужна только оболочка; исполнитель - интерактивный агент в терминале herdr-core.

## Терминал исполнителя

| Элемент | Правило |
|---|---|
| Имя | `tool-<module>` (MCP), `tool-<module>-<profile>` (служебный репозиторий) |
| Запуск | при первом вызове, в папке модуля, через `env` с `PATH`, локалью и прокси (herdr-core запускает программы со своим окружением) |
| Время жизни | остаётся после вызова; один запрос за раз (занятый исполнитель - код 3). Закрытие его вкладки в Herdr App завершает исполнителя; следующий вызов запускает его снова |
| Видимость | всегда в Herdr App. `space = "caller"` (по умолчанию): space вызывающего терминала. `space = "module"`: space, вкладки которого сейчас работают внутри папки модуля; создаётся, если такого нет. Ключ реестра `space`, флаг `--space` |
| Сброс | перед каждым запросом команда новой беседы среды (`/clear`, `/new`): один запрос - одна беседа |

Herdr App хранит раскладку в документе herdr-core `herdr-app` (space, вкладки, терминалы). Терминал
с меткой `herdr.space=<id>` получает вкладку в этом space. Space сопоставляется по текущей рабочей
папке его терминалов, поскольку сохранённое поле `folder` - папка, в которой space был создан. Новый
space добавляется через `doc.set` с проверкой версии.

## Запрос

Запрос содержит правила исполнителя (границы, режим записи, запрет вывода секретов, запрет ожидания
человека), задачу, путь к файлу ответа и, для служебного репозитория, каталог файлов для
вызывающего. Правила передаются вместе с запросом, поэтому любая среда получает их одинаково. Файл
ответа заканчивается строкой `DONE` или `FAILED: <причина>`; `FAILED: needs: <вопрос>` - вопрос
человеку.

## Завершение

Правила взяты из herdr-gsd-template: сначала устойчивое свидетельство, затем факты терминала.

1. Единственное доказательство завершения - маркер файла ответа (`DONE`, `FAILED`).
2. Статус терминала сам по себе ожидание не завершает. Счётчик ходов исполнителя должен перейти
   дальше запроса; после этого файлу даётся `HERDR_AGENT_KIT_GRACE` секунд (20), поскольку статус и
   запись файла не упорядочены.
3. Ход, закончившийся без маркера, сообщается вместе с концом экрана исполнителя: обычно там вопрос
   или ошибка, выведенные вместо записи файла.
4. `blocked` (диалог разрешения или вопрос) - код 4: отвечает человек в Herdr App или через
   `hc attach <terminal>`, но не вызывающий агент.

Синхронный вызов ждёт в одной блокирующей команде. С `--async` вызов выводит идентификатор задачи;
далее:

| Вызывающий | Сигнал |
|---|---|
| любой | одна блокирующая команда `wait <module> <task>` (фоновой командой, где среда это позволяет) или `result <module> <task>` (0 готово, 3 ещё выполняется); без циклов опроса |
| внутри herdr | терминал-наблюдатель `w-<module>-<task>`, дочерний для вызывающего, выполняет `wait`; при его завершении herdr оставляет заметку вызывающему (`hc wait --children any` ждёт её) |

## Коды выхода

| Код | Значение | Действие вызывающего |
|---|---|---|
| 0 | ответ готов, путь в stdout | прочитать файл |
| 1 | ошибка или таймаут | прочитать stderr и файл |
| 2 | ошибка вызова или конфигурации | исправить вызов |
| 3 | исполнитель занят или задача ещё выполняется | повторить позже |
| 4 | нужен человек | попросить человека ответить в Herdr App |
| 5 | запись запрещена | спросить человека; `--write` только после согласия |
| 6 | сбой профиля (служебный репозиторий) | спросить человека, затем `--profile <name>` из stderr |

## Аудит

Каждый запрос и результат - строка в `~/.cache/herdr-agent-kit/audit.jsonl`; задача служебного
репозитория хранит `task.json`, `answer.md` и свои файлы в `~/.cache/herdr-agent-kit/<module>/<task>/`.
