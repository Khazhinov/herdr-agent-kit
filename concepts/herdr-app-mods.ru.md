# Моды Herdr App: группы spaces и лимиты агентов

Две панели для боковой панели Herdr App. Это обычные моды Herdr App (JavaScript на gpui-kit в
`mods/<name>/` домашней папки приложения); в herdr-core они ничего не меняют.

## 1. Группы spaces (`herdr-app/space-groups`)

Штатный список `spaces` с папками. Всё штатное поведение сохраняется: аватары, worktree под своим
репозиторием, разделы по машинам, ветка git и опережение/отставание, меню space.

| Действие | Результат |
|---|---|
| Кнопка с папкой в заголовке Spaces | новая группа на машине показанного space |
| Перетащить space на группу | space попадает в группу, в конец |
| Перетащить space на space в группе | space встаёт перед ним или после него, по половине под указателем |
| Перетащить space на space вне групп | штатная перестановка (`space.move`) |
| Перетащить space ниже последней строки | space выходит из всех групп |
| Перетащить группу на середину / край группы | группа становится подгруппой / встаёт перед ней или после неё |
| Перетащить группу на space или ниже последней строки | в группу этого space / на верхний уровень |
| Щелчок по группе | свернуть или развернуть (аккордеон) |
| Правый щелчок по группе | переименовать, новая подгруппа, расформировать (spaces и подгруппы переходят к родителю) |

Строка группы показывает число spaces в ней, включая подгруппы, и самое срочное состояние агентов
внутри: индикатор вращения (работает), цветная точка (ждёт человека, завершил), полая точка (только
простаивающие агенты). Группа принадлежит одной машине; перетаскивание между машинами не
выполняется. В узкой панели группа - строка со стрелкой и состоянием (щелчок сворачивает её),
spaces сохраняют свои номера.

Группы являются представлением этого экрана. Они хранятся в общем состоянии приложения
(`shared("space-groups")`) и никогда не попадают в документ ядра `herdr-app`. Идентификаторы,
имена, папки и вкладки spaces не меняются, поэтому инструменты, находящие space по текущим
каталогам его терминалов (`tool_ask.py --space module`, `[workers] space = "project"` шаблона GSD),
работают одинаково с группами и без них. Исчезнувший space удаляется из группы, когда раскладка его
машины снова доступна.

## 2. Лимиты агентов (`herdr-app/agent-limits`, `limits.py`)

По одной строке на агента: значок, имя и каждое окно использования, о котором сообщает среда
(5 ч, 7 дней, месяц, предел расходов), в виде процента с тонкой полосой. Цвет следует за
использованием: зелёный, с 70 % цвет темы «работает», с 90 % цвет «ждёт человека». У каждого окна
указано время сброса в формате даты и времени системы: время сегодня, день недели и время в пределах
недели, дата позже. Формат читается один раз из `Get-Culture` в Windows и `locale -k LC_TIME` в
остальных системах, поскольку в среде модов нет `Intl`. Агент с доступными сбросами лимитов (их
выдаёт Codex) показывает их число рядом с именем. Подсказка окна
показывает использовано, осталось и полное время сброса; подсказка имени - возраст данных; щелчок по
заголовку обновляет данные (они обновляются каждые 10 секунд). Лимиты Claude приходят в ответах его API, поэтому меняются при запросе любой сессии, и
обёртка сразу их записывает. Строки с данными старше 3 часов приглушены. В узкой панели у каждого
агента видны значок, процент и полоса самого заполненного окна. Окно, обновившееся после последнего снимка, показывает `new`: его использование ещё
ничем не подтверждено.

`limits.py` (стандартная библиотека) собирает данные там, где лежит набор; мод запускает его на
этой машине herdr (`source.json`, его пишет установщик). Настройки - раздел `[limits]` реестра:

| Ключ | Значение |
|---|---|
| `agents` | какие агенты и в каком порядке; по умолчанию `["claude", "codex"]` |
| `show` | `used` (0 % = ничего не израсходовано, по умолчанию) или `left` (100 % = всё осталось) |
| `[limits.commands]` | любой другой агент (Cursor, Antigravity и т. д.): команда, печатающая `{"windows": [{"name", "used", "resets_at"}]}`, при необходимости `"resets": {"available", "expires_at"}` |

Встроенные источники:

| Агент | Источник |
|---|---|
| Claude Code | `rate_limits` из входных данных statusLine. `limits.py statusline -- <прежняя команда>` оборачивает statusLine, хранит снимок каждой сессии и запускает прежнюю команду с теми же входными данными, поэтому видимая строка не меняется. Простаивающая сессия показывает последнее увиденное, возможно до сброса, поэтому по каждому окну выбирается самый поздний `resets_at`, а в нём наибольшее использование. Снимки собственной обёртки шаблона GSD также читаются. |
| Codex | более свежее из двух: последние `rate_limits` в журналах `~/.codex/sessions` (пишутся на каждом ходе Codex, читаются при каждом обновлении) и `codex app-server` `account/rateLimits/read` (видит и другие машины и доступные сбросы лимитов, `rateLimitResetCredits`; запрашивается не чаще раза в 30 с, один запуск занимает около секунды) |
| Kimi Code | `GET /usages` на настроенном официальном endpoint Kimi Code. Показываются доступные окна 5 ч, 7 дней и общий месячный лимит; отсутствующие окна пропускаются. `limit_month_code` является долей общего месячного расхода, приходящейся на Kimi Code, и выводится в подсказке `month`, а не отдельным лимитом. После обновления окна прежняя разбивка скрывается до нового чтения. Ответы и ошибки кэшируются на 90 с. При сбое остаются окна и исходная отметка времени последнего успешного чтения вместе с ошибкой. Произвольные API-хосты и перенаправления запрещены. |

Для Codex + Kimi задайте `[limits] agents = ["codex", "kimi"]`; изменения statusLine Claude не нужны.
Настройки провайдера Kimi читаются из `config.toml` в `~/.kimi-code` (или `KIMI_CODE_HOME`). Выберите один способ авторизации: `oauth`, непустой `api_key` или `api_key_env` с именем переменной среды. Конфликтующие способы отклоняются. Пробелы по краям строковых значений удаляются. Указанная переменная должна быть непустой и доступной процессу сборщика, в том числе при запуске на другой машине; отсутствие или пустое значение дают ошибку конфигурации. При использовании API-ключа продление OAuth не запускается.

При OAuth сборщик проверяет соответствие настроенного credential slot действующему официальному API endpoint и OAuth host, затем читает существующий credential CLI. Несоответствия, включая несовместимые переопределения `KIMI_CODE_BASE_URL`, `KIMI_CODE_OAUTH_HOST` или `KIMI_OAUTH_HOST`, отклоняются до чтения credential и сетевых запросов. Согласуйте среду сборщика с `config.toml` и выполните вход через Kimi; сборщик не выбирает другой slot молча. Поддерживается только файловое хранение OAuth. Токен с refresh token, истекающий не более чем через 60 с или без времени истечения, вызывает штатное продление. Для этого требуется совместимый Kimi Code CLI в PATH или `KIMI_CODE_HOME/bin` (локальный API и реестр процессов проверены с 2.5.0). Сборщик кратковременно запускает собственный авторизованный `kimi web --no-open` на случайном порту только loopback и вызывает API квоты. Блокировки, ротацию и атомарную запись выполняет Kimi; сборщик перечитывает сохранённый результат и завершает свой сервер. Браузер, агентская сессия и запрос к модели не запускаются. Значения credential не попадают в кэш набора и сообщения об ошибках.

После OAuth HTTP 401 сборщик перечитывает сохранённый credential, учитывая параллельную ротацию CLI. Если этому результату требуется обычное продление, штатный helper может быть вызван один раз. Другой access token допускает один финальный запрос квоты. API квоты совместимого CLI **не** предоставляет принудительное продление формально свежего токена: неизменившийся отклонённый токен или повторный 401 дают ошибку с указанием повторно авторизоваться через `kimi /login`. На одну попытку сбора разрешены не более двух прямых запросов квоты и одного штатного helper; helper может выполнить собственный запрос квоты. При 401 для API-ключа сообщается ошибка ключа. Другие HTTP-ошибки и сбои соединения не запускают восстановление или повторы. После ошибки следующая попытка происходит через интервал кэша 90 с.

## 3. Установка

```sh
herdr-app/install.py --dry-run --claude-statusline   # что будет изменено
herdr-app/install.py --claude-statusline
```

Установщик копирует оба мода, пишет `source.json` и в каждой пользовательской раскладке со штатной
боковой панелью переключает блок `spaces` на `space-groups` и добавляет блок `agent-limits` под
списком агентов. Раскладки Herdr доступны только для чтения; если есть только `main`, создаётся её
копия `kit`. `--claude-statusline` один раз оборачивает глобальный statusLine в
`~/.claude/settings.json` (резервная копия: `settings.json.pre-agent-limits`). Повторный запуск нужен
после обновления приложения или изменения `[limits] agents`. Удаление: вернуть блоку мод `spaces`,
удалить блок `agent-limits` и папки обоих модов.

Установщик шаблона GSD строит свою раскладку `gsd-mission-control` из `main` заново и сохраняет
блоки боковой панели, изменённые или добавленные другими установщиками, поэтому порядок установки
не важен.
