# Подключённые проекты

[English](linked-projects.md) | Русский

## Файлы в проекте

`tool_ask.py link <project> <module>...` записывает три уровня. Под git проекта находится только
первый, и в нём нет путей машины.

| Файл | Содержание | В git |
|---|---|---|
| `AGENTS.md` (и `CLAUDE.md`, если он не подключает `AGENTS.md`) | одна универсальная строка: у проекта есть подключённые внешние инструменты и репозитории, их перечень - в `.agent-tools/TOOLS.md`; читать его до поиска MCP-инструментов и до работы, которую предлагает подключённый репозиторий | да |
| `.agent-tools/TOOLS.md` | перечень: строка на каждый подключённый модуль (вид, что предоставляет, файл описания, последнее изменение) и правила вызова: команды, файл ответа, `--async` и его сигналы, согласование записи, коды выхода | нет (`.git/info/exclude`) |
| `.agent-tools/<module>.md` | описание одного модуля: строка вызова, разрешение записи, функции с сигнатурами и пояснениями параметров (служебный репозиторий) или имена инструментов (MCP), пять последних изменений | нет |

Строка-указатель одинакова во всех проектах и средах: любой агент, читающий `AGENTS.md`, находит
перечень, а перечня достаточно для вызова любого модуля. Сигнатуры не попадают в контекст агента,
пока он не откроет файл описания или не запросит `card <module> <name>`.

## Поддержание проектов в актуальном состоянии

| Изменение | Что обновляет проекты |
|---|---|
| манифест служебного репозитория (новая функция, параметр, профиль) | автоматически: карточка пересобирается, если манифест новее, при `call`, `card`, `link` и `sync`; изменение записывается в журнал, подключённые к модулю проекты перезаписываются |
| MCP-серверы или их конфигурация | `refresh <module>` (запускает серверы), затем `sync` |
| реестр (описание, `allow_write`, удалённый модуль) | `sync` |

`sync --dry-run` перечисляет проекты, которые изменятся; `sync` также сообщает о подключённых
проектах, которых больше нет, и о модулях, удалённых из реестра. Строка журнала имеет вид
«2026-11-04 15:20: added `summary`; changed `draft`» и появляется в перечне (последнее изменение) и в
файле модуля (последние изменения). Агент, прочитавший файлы раньше, увидит изменение при следующем
открытии; `call`, пересобравший карточку, сообщает об этом в stderr.

`unlink <project> [module...]` удаляет файлы модулей; без перечня модулей удаляется и перечень.

## Применение без этого кода

Дать каждому проекту одну строку-указатель под git, перечень подключённых возможностей с правилами
вызова вне git и по одному файлу вне git на каждую возможность. Пересобирать их из источника истины
(`tools/list` MCP, манифесты служебных репозиториев) при каждом его изменении, с датированной строкой
журнала.
